# v3.1 Multi-Provider Compute Refactor — Review Round 1

**Date**: 2026-02-14
**Models**: Claude Opus 4.6 (Gemini failed — E2BIG shell error)
**Context**: ~377k tokens

## Findings

### Major (3 found, 3 fixed)

- **M1**: `secrets.rs:44` used `presigned_get_url_by_key()` (server-facing S3 client) instead of `presigned_get_url_by_key_for_compute()`. Broken in local dev with MinIO (generates localhost URL unreachable from containers). **Fixed.**
- **M2**: Wave error handling broke immediately on first node failure, dropping remaining `JoinHandle`s. This leaked running compute tasks (Docker containers, Fly machines). **Fixed** — remaining handles now collected and awaited before cleanup.
- **M5**: Secrets R2 key was `secrets/{job_id}.json` — per-job, not per-node. Parallel nodes in the same wave would overwrite each other's secrets blobs. **Fixed** — key now `secrets/{job_id}/{node_name}.json`.

### Minor (10 found, 5 fixed)

- **m7**: No timeout on Fly create machine HTTP request. **Fixed** — added 30s timeout.
- **m8**: No timeout on Fly get_machine_state, destroy_machine, list_machines. **Fixed** — added 30s timeouts.
- **m9**: Output temp key used random UUID, not correlated with job/node. **Fixed** — now `compute-output/{job_id}/{node_name}.tar.gz`.
- **m10**: Redundant `docker.enabled` check in ComputeRegistry (from_env_optional already returns None when disabled). **Fixed** — removed inner check.
- m1: Source URL TTL may be insufficient for deep multi-wave DAGs. **Accepted** — current buffer is adequate for expected DAG depth.
- m2: Silent symlink omission in source tarball. **Accepted** — symlinks rare in data transforms.
- m3: Nondeterministic env var HashMap ordering. **Accepted** — no correctness impact.
- m4: Docker CLI exposes presigned URLs in /proc. **Accepted** — short-lived URLs, defense-in-depth note added.
- m5: Output tarball path traversal concern. **Not applicable** — tar crate 0.4.44 has built-in protection.
- m6: PlatformFingerprint detected on server, not container. **Accepted** — intentional design (same arch).

### Notes (10)

- n1: Clean object safety via boxed futures (good)
- n2: Source uploaded once per job (good optimization)
- n3: Init script unsets sensitive env vars (good security)
- n4: Rate limiting is advisory/TOCTOU (documented tradeoff)
- n5: Fly orphan cleanup is conservative (good)
- n6: Test infra uses compose services (good)
- n7: Test coverage gaps (providers endpoint, secrets E2E, multi-node DAG, Fly, mock backend)
- n8: curl vs python3 inconsistency in init script (both required anyway)
- n10: Collection input support appears incomplete (is_collection hardcoded false)
