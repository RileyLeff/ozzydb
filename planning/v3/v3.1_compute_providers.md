# v3.1 Architecture Addendum

Three areas of cleanup to bring the codebase in line with v3 principles:

1. **Multi-provider compute** — replace single-backend model with a provider registry, unified I/O, user-selectable machines
2. **Storage: require R2/MinIO** — remove local-only fallback, read-through cache, and byte-proxying code paths
3. **Test infrastructure** — Docker Compose for tests, rewrite integration/E2E tests to use MinIO

---

## 1. Multi-Provider Compute

### Problem

`BackendSelector` picks **one** compute backend at server startup (Fly if R2 is configured, else Docker, else disabled). The orchestrator branches on `is_fly` throughout execution to handle two different I/O strategies (bind mounts for Docker, presigned URLs for Fly).

This creates three problems:

1. **Only one provider active at a time.** A server can't offer both Fly (CPU) and a GPU provider simultaneously.
2. **Two I/O paths.** Docker uses bind mounts + local filesystem; Fly uses presigned URLs. The `is_fly` branching is scattered across the orchestrator, violating the principle that the trait should be the abstraction boundary.
3. **Users can't choose.** `NodeDef.machine` exists in the TOML parser but is ignored by the orchestrator.

### Provider registry

The server maintains a **registry of active compute providers**, not a single backend. Each provider is a named implementation of `ComputeBackend`.

```rust
/// All active compute providers, keyed by name.
/// Stored in AppState. Empty map = compute disabled.
pub struct ComputeRegistry {
    providers: HashMap<String, Arc<dyn ComputeBackend>>,
    default_provider: Option<String>,
}

impl ComputeRegistry {
    /// Look up a provider by name, or return the default.
    pub fn resolve(&self, machine: Option<&str>) -> Result<&dyn ComputeBackend, ApiError>;

    /// List all active provider names (for API/frontend).
    pub fn active_providers(&self) -> Vec<String>;
}
```

`AppState.compute: Option<BackendSelector>` becomes `AppState.compute: ComputeRegistry`.

### Provider configuration

Each provider has its own config block + an `enabled` toggle. The server reads all of them at startup and registers the enabled ones.

```rust
pub struct ComputeConfig {
    /// Timeout in seconds for compute jobs (applies to all providers).
    pub timeout_secs: u64,
    /// Default provider name (e.g., "fly"). Must match a registered provider.
    pub default_provider: Option<String>,
}

pub struct DockerProviderConfig {
    pub enabled: bool,
    pub runtime: Option<String>,   // e.g., "runsc"
    pub memory_limit: String,
    pub cpu_limit: String,
    pub tmpdir: String,
    pub tmpfs_size: String,
}

pub struct FlyProviderConfig {
    pub enabled: bool,
    pub api_token: String,
    pub app_name: String,
    pub region: String,
    pub api_url: String,
    pub cpu_kind: String,
    pub cpus: u32,
    pub memory_mb: u32,
}

// Future: GpuProviderConfig, EcsProviderConfig, etc.
```

Env var mapping:

| Env var | Purpose |
|---------|---------|
| `COMPUTE_TIMEOUT_SECS` | Global timeout for all providers |
| `COMPUTE_DEFAULT_PROVIDER` | Default provider name (e.g., "fly") |
| `DOCKER_COMPUTE_ENABLED` | Enable Docker provider |
| `DOCKER_COMPUTE_RUNTIME` | Docker runtime (e.g., "runsc") |
| `DOCKER_COMPUTE_MEMORY_LIMIT` | Docker memory limit |
| `DOCKER_COMPUTE_CPU_LIMIT` | Docker CPU limit |
| `DOCKER_COMPUTE_TMPDIR` | Docker workspace tmpdir |
| `FLY_API_TOKEN` | Enable + configure Fly provider |
| `FLY_APP_NAME` | Fly app name |
| `FLY_REGION` | Fly region |
| ... | (existing Fly vars unchanged) |

A provider is registered if its `enabled` flag is true (Docker) or its required credentials are present (Fly). If no providers are registered, compute is disabled (empty registry).

### Unified I/O

**All providers use presigned URL I/O.** There is one init script, one I/O contract. The `is_fly` branching in the orchestrator is eliminated entirely.

The contract between orchestrator and container:

| Env var | Purpose |
|---------|---------|
| `OZZY_PARAMS` | JSON params object |
| `OZZY_INPUT_MANIFEST` | JSON input manifest (names, paths, content types) |
| `OZZY_INPUT_DOWNLOADS` | JSON array of `{name, url, path}` — presigned GET URLs for inputs |
| `OZZY_SOURCE_DOWNLOAD` | Presigned GET URL for source code tarball (if source-based transform) |
| `OZZY_OUTPUT_UPLOAD_URL` | Presigned PUT URL for output tarball |
| `OZZY_SECRETS_URL` | Presigned GET URL for secrets JSON blob (if secrets declared) |
| `OZZY_RUNNER_SCRIPT_B64` | Base64-encoded runner script |
| `OZZY_PARAM_*` | Individual param env vars |

The init script (currently `generate_fly_init()`, renamed to just `generate_init()`) handles all of this. It runs identically whether the container is a Fly Machine, a local Docker container, an ECS task, or anything else.

**Docker-specific change:** Docker containers must have network access to reach MinIO (local dev) or R2 (self-hosted with Docker compute). The current `--network none` default for Docker is replaced with network access to the storage backend. Sandboxing (gVisor) still provides isolation — network policy is orthogonal.

### ComputeBackend trait

The trait becomes simpler. It no longer returns `ComputeResult` with local filesystem paths — instead, the orchestrator handles output retrieval uniformly via presigned URLs.

```rust
pub trait ComputeBackend: Send + Sync {
    /// Execute a transform container. The container will:
    /// 1. Download inputs from presigned URLs (OZZY_INPUT_DOWNLOADS)
    /// 2. Run the transform
    /// 3. Upload output to presigned PUT URL (OZZY_OUTPUT_UPLOAD_URL)
    ///
    /// The backend is responsible for:
    /// - Creating the container with the given image + env vars
    /// - Waiting for completion (or timeout)
    /// - Returning exit code and logs
    /// - Cleaning up the container
    fn run(
        &self,
        request: &ComputeRequest,
    ) -> impl Future<Output = Result<ComputeResult>> + Send;

    /// Provider name (e.g., "fly", "docker").
    fn name(&self) -> &str;
}
```

`ComputeRequest` drops the fields that were only needed for bind-mount I/O:

```rust
pub struct ComputeRequest {
    pub image: String,
    pub env_vars: HashMap<String, String>,  // all OZZY_* vars, params, secrets URL
    pub timeout_secs: u64,
    pub memory_limit: Option<String>,
    pub cpu_limit: Option<String>,
    pub network: bool,
    pub runtime: Option<String>,
}
```

Removed: `runner_script`, `runner_ext`, `init_script`, `inputs: Vec<InputSpec>`, `source_dir`. These are all encoded into `env_vars` by the orchestrator before dispatch (runner script as `OZZY_RUNNER_SCRIPT_B64`, inputs as `OZZY_INPUT_DOWNLOADS`, etc.).

`ComputeResult` drops the local filesystem fields:

```rust
pub struct ComputeResult {
    pub exit_code: i32,
    pub logs: String,
    pub duration_ms: u64,
}
```

Removed: `output_dir`, `workspace_dir`. Output is on R2/MinIO (uploaded by the container via presigned PUT). The orchestrator downloads it from storage after the container exits.

### Machine resolution in the orchestrator

When executing a node, the orchestrator resolves `node_def.machine` to a provider:

```
1. If node_def.machine is Some(name) → look up name in ComputeRegistry
2. If node_def.machine is None → use ComputeRegistry.default_provider
3. If no default → error (compute not configured)
```

The resolved provider name is stored in the job's per-node status so the admin dashboard can show which provider ran each node.

### User-facing machine names

Users specify machines in `ozzy.toml`:

```toml
[endpoints.my_endpoint.nodes]
preprocess = { transform = "qc" }                        # uses default provider
train      = { transform = "model", machine = "gpu" }    # uses "gpu" provider
```

Machine names are server-defined (e.g., "fly", "docker", "gpu"). The server exposes available machines via an API endpoint:

```
GET /v1/compute/providers

Response:
{
  "default": "fly",
  "providers": [
    { "name": "fly", "description": "Fly.io Firecracker VMs (CPU)" }
  ]
}
```

If a user requests a machine that isn't active on the server, the job fails with a clear error: "Compute provider 'gpu' is not available on this server."

### Orchestrator changes

The orchestrator simplifies significantly. The current flow has `is_fly` branching in ~6 places. The new flow:

1. **Upload source tarball to R2** (once per job, if source-based transforms exist)
2. **For each node in each wave:**
   a. Check materialized cache (unchanged)
   b. Resolve provider via `registry.resolve(node_def.machine.as_deref())`
   c. Generate presigned URLs for inputs, output, source, secrets (same for all providers)
   d. Encode runner script as base64 into `OZZY_RUNNER_SCRIPT_B64`
   e. Build `ComputeRequest` with all env vars
   f. Call `provider.run(&request)`
   g. On success (exit 0), download output from R2 via presigned GET URL
   h. Store output, update materialized cache (unchanged)
3. **Clean up** source tarball, secrets blobs (unchanged)

No `is_fly` checks. No bind mount logic. No local file hydration for inputs. No local output directory reading.

### Docker backend changes

`DockerBackend::run()` becomes:

1. `docker run` with env vars (no bind mounts except tmpfs if configured)
2. Container downloads inputs, runs transform, uploads output (via init script)
3. Wait for exit, collect logs
4. Return `ComputeResult { exit_code, logs, duration_ms }`

The container needs network access to reach MinIO (local dev) or R2 (self-hosted). For local dev, compute containers need to join the Docker Compose network or use host networking to reach MinIO.

### Fly backend changes

Minimal. `FlyBackend::run()` already uses presigned URLs. The main change is that it no longer needs to download output to a local temp dir and extract it — the orchestrator handles that uniformly.

### Validation

At push time: server validates that every `machine` referenced in `ozzy.toml` nodes corresponds to an active provider. If not, the push succeeds (the machine might become available later) but a warning is returned. At fetch time: if the requested machine isn't available, the job fails immediately with a clear error.

## 2. Storage: Require R2/MinIO, Remove Local-Only Fallback

### Problem

`ContentStorage` has two modes:

1. **R2 configured**: R2 is source of truth, local disk is a read-through cache
2. **R2 not configured**: Local disk is the primary store

This dual-mode creates unnecessary code paths. In v3, R2/MinIO is always available (prod has R2, local dev has MinIO via `docker-compose.dev.yml`). The server never needs to proxy blob bytes — downloads use 302 redirects to presigned URLs. The local read-through cache accumulates files on the VPS that nobody reads.

### Changes

**ContentStorage becomes R2/S3-only:**

- `remote_store: Option<Arc<dyn ObjectStore>>` → `remote_store: Arc<dyn ObjectStore>` (always present)
- `s3_client: Option<aws_sdk_s3::Client>` → `s3_client: aws_sdk_s3::Client` (always present)
- `bucket: Option<String>` → `bucket: String` (always present)
- `cache_dir: PathBuf` → **deleted**
- `from_config()` errors if R2 config is missing: "R2/S3 storage configuration is required. Set R2_ENDPOINT, R2_BUCKET, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY."

**Remove local file I/O from ContentStorage:**

| Method/field | Change |
|-------------|--------|
| `cache_dir` field | Delete |
| `local_path()` | Delete |
| `ensure_parent()` | Delete |
| `cache_local_best_effort()` | Delete |
| `store()` local-only branch | Delete (only R2 path remains) |
| `store_with_hash()` local-only branch | Delete |
| `get()` local-first check + hydration | Delete (only R2 path remains) |
| `get_stream()` local-first check | Delete |
| `exists()` local-first check | Delete |
| `delete()` local cleanup | Delete |
| `list_by_prefix()` local fallback | Delete |
| `metadata()` local-first check | Delete |
| `store_stream()` local-only buffer fallback | Delete |
| `has_remote()` | Delete (always true) |

**Remove byte-proxying fallback from API endpoints:**

| File | Change |
|------|--------|
| `api/v1/data.rs` download handler | Remove `if state.storage.has_remote() { ... } else { proxy bytes }` — always use presigned redirect |
| `api/v1/jobs.rs` output handler | Same — always use presigned redirect |

**Remove from config:**

| Item | Change |
|------|--------|
| `Config.cache_dir` field | Delete |
| `LOCAL_STORAGE_PATH` env var | Delete |
| `Config.r2: Option<R2Config>` | `Config.r2: R2Config` (required, not optional) |
| `docker-compose.dev.yml` `dev_cache` volume | Delete |
| `docker-compose.dev.yml` `LOCAL_STORAGE_PATH` env var | Delete |
| `docker-compose.prod.yml` `ozzy_data` volume | Delete (was for local cache) |

**Server startup behavior:** If R2 env vars are missing, the server refuses to start with a clear error. This is the right behavior — nothing works without object storage anyway.

## 3. Test Infrastructure

### Problem

Both `integration_tests.rs` and `e2e_tests.rs` use `r2: None` — they run entirely on the local-only storage path that's being deleted. They spin up testcontainers for Postgres but have no MinIO. The `storage_tests.rs` already connects to real MinIO when env vars are set.

### Docker Compose for tests

A lightweight `docker-compose.test.yml` (or reuse `docker-compose.dev.yml` minus the server) that provides Postgres + MinIO for tests:

```yaml
# docker-compose.test.yml
# Provides Postgres + MinIO for integration and E2E tests.
# Usage: docker compose -f docker-compose.test.yml up -d
#        just test-docker
#        just test-e2e

services:
  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: ozzy_test
      POSTGRES_PASSWORD: ozzy_test
      POSTGRES_DB: ozzy_test
    ports:
      - "5433:5432"    # non-default port to avoid conflicts with dev
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ozzy_test"]
      interval: 3s
      timeout: 2s
      retries: 5

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    ports:
      - "9002:9000"    # non-default port to avoid conflicts with dev
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 3s
      timeout: 2s
      retries: 5

  minio-init:
    image: minio/mc:latest
    depends_on:
      minio:
        condition: service_healthy
    entrypoint: >
      /bin/sh -c "
        mc alias set local http://minio:9000 minioadmin minioadmin;
        mc mb --ignore-existing local/ozzy-test;
      "
```

### Test infrastructure rewrite

**`TestServer::start()` changes (both `integration_tests.rs` and `e2e_tests.rs`):**

- Remove `testcontainers` Postgres — connect to Compose-provided Postgres at `localhost:5433`
- Remove `_storage_dir: tempfile::TempDir` — no local storage
- Set `r2: Some(R2Config { endpoint: "http://localhost:9002", bucket: "ozzy-test", ... })`
- Each test run gets a unique DB schema (or `CREATE DATABASE` per test) to isolate concurrent runs
- Each test run gets a unique R2 prefix to isolate storage

**Remove tests for deleted code paths:**

| Test | Reason |
|------|--------|
| `storage_tests::test_store_stream_local_fallback` | Local fallback deleted |
| `storage_tests::test_presigned_url_without_remote_fails` | R2 always configured (test becomes meaningless) |

**Justfile updates:**

```just
# Start test infrastructure
test-infra-up:
    docker compose -f docker-compose.test.yml up -d
    docker compose -f docker-compose.test.yml exec -T minio-init true 2>/dev/null || sleep 3

# Stop test infrastructure
test-infra-down:
    docker compose -f docker-compose.test.yml down

# Run integration tests (requires test infra)
test-docker:
    cargo test -p ozzy-server --test integration_tests -- --ignored

# Run E2E tests (requires test infra + Docker for compute)
test-e2e:
    cargo test -p ozzy-server --test e2e_tests -- --ignored

# Run all tests
test-all:
    cargo test --workspace
    cargo test -p ozzy-server --test integration_tests -- --ignored
    cargo test -p ozzy-server --test e2e_tests -- --ignored
```

### Env vars for tests

Tests read from env vars (with sensible defaults for the Compose setup):

```rust

            .unwrap_or_else(|_| "minioadmin".into()),
        secret_access_key: std::env::var("TEST_R2_SECRET_ACCESS_KEY")
            .unwrap_or_else(|_| "minioadmin".into()),
        region: "us-east-1".into(),
    }
}
```

## Implementation Order

This is a refactor of existing working code, not new feature development. The system works today — the goal is to clean it up and make it extensible.

1. **Storage cleanup** — Remove local-only fallback, `cache_dir`, `has_remote()`, byte-proxying. Make R2 required. This is the smallest diff and unblocks test infrastructure work.

2. **Test infrastructure** — Create `docker-compose.test.yml`. Rewrite `TestServer::start()` in integration/E2E tests to use Compose-provided Postgres + MinIO. Remove `testcontainers` dependency. Verify all existing tests pass.

3. **Unified I/O** — Collapse `generate_docker_init()` into `generate_init()`. Remove bind mount logic from `DockerBackend`. Docker containers use presigned URLs to MinIO. Remove all `is_fly` branching from orchestrator.

4. **Slim ComputeRequest/ComputeResult** — Remove filesystem-oriented fields. Orchestrator handles presigned URL generation and output retrieval uniformly.

5. **ComputeRegistry** — Replace `BackendSelector` with `ComputeRegistry`. Wire `node_def.machine` resolution into orchestrator. Add `GET /v1/compute/providers` endpoint.

6. **Config restructure** — Split `ComputeConfig` into global + per-provider configs. Update env var names. Update all docker-compose files.

7. **Final cleanup** — Delete remaining dead code per inventory. Update `docker-compose.prod.yml`. Update README, CLAUDE.md, getting_started docs.
